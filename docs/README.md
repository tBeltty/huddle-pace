# HuddlePace Engineering Guidelines & Golden Rules

This directory contains the normative engineering standards for HuddlePace, designed to match HuddlePace's TypeScript, Prisma, and Slack Socket Mode architecture.

---

## The Guidelines

1. **[Coding Standards & Architecture](guidelines/CODING.md)**: File structure, naming, single responsibility, immutability, and error handling.
2. **[UI, Block Kit & Styling](guidelines/UI_SLACK_BLOCKS_CSS.md)**: Visual hierarchy, progress bar aesthetics, and Atmos UI principles in Slack Block Kit and companion web interfaces.
3. **[Editorial Standards & Writing Hygiene](guidelines/EDITORIAL_STANDARDS.md)**: Direct human cadence, banned tropes (no binary contrasts, no colon reveals), and concise notifications.
4. **[Repository & Git Hygiene](guidelines/REPOSITORY_HYGIENE.md)**: Conventional commits, public-facing professional terminology, CI naming standards, and secret isolation.
5. **[Infrastructure & Deployment](guidelines/INFRASTRUCTURE.md)**: VPS isolation, systemd daemon management, SQLite durability, and zero-ingress Socket Mode architecture.
6. **[Security & Token Standards](guidelines/SECURITY.md)**: Secrets isolation, least privilege Slack scopes, and Zod runtime schema validation.
7. **[Definition of Done (DoD)](guidelines/DEFINITION_OF_DONE.md)**: Non-negotiable checklist before any feature or PR is signed off.
